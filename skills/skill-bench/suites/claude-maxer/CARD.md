# Benchmark card: `claude-maxer`

## What is measured

- **Trigger** — does the model call `Skill(claude-maxer)` when it should (recall), and stay quiet when it shouldn't (precision / false-positive rate)?
- **Behavior** — once the skill is used, does the reply meet the skill's own documented contract? Scored by hard checks (gates) plus a binary rubric graded by a blind LLM judge.

## Capability spec (derived from SKILL.md at creation)

Trigger claims
- **T1**: fires on questions about Claude Pro/Max subscription usage limits (how close, am I about to be cut off, headroom).
- **T2**: fires on questions about the 5-hour rolling window (remaining, reset time, why it reset when it did).
- **T3**: fires on questions about the weekly (7-day) quota.
- **T4**: fires whenever "claude-maxer" is named.
- **T5**: fires on questions about the routine it manages (keep-alive ping, unattended hourly work loop, its digests/PRs) even when not named.

Non-trigger claims
- **N1**: the vault Tasks queue belongs to `tasks-queue` (formerly `vault-tasks`).
- **N2**: provider routing / the proxy belongs to `model-switch`.
- **N3**: other neighbouring skills (skill-bench, context-summarize, nextcloud-paper) and generic cron jobs unrelated to usage.
- **N4**: Anthropic *API* rate limits (tier limits) are not the subscription window.
- **N5**: cue words ("window", "weekly", "limit", "rate limit") used in another sense.
- **N6**: off-topic requests.

Behavior claims (answers must come from the skill's documentation; trials have Bash disabled)
- **B1**: the 5h gate is a ramped ceiling (0/25/50/75/95 by hour); hour 0 is dead so interactive work gets first claim.
- **B3**: work selection: vault Tasks item first, then weighted draw over skill-audit/todo-triage/dep-audit; both digests disabled (weight 0).
- **B4**: loop stops at gate skip, MAX_ITERATIONS=3, or MAX_MINUTES=40.
- **B5**: repo work types go on a `claude-maxer/…` branch with a draft PR; vault-task iterations commit straight to master in `/data/apps/myfollows`.
- **B6**: `crontab -l` is the source of truth for enabled state, not the doc.
- **B7**: querying the OAuth usage endpoint is metadata-only: no quota consumed, window not opened.
- **B8**: missing `resets_at` falls back to a 25% ceiling to avoid a deadlock.
- **B9**: `MAXER_FORCE_TYPE=news-digest` runs a disabled digest by hand.

Not covered: live usage numbers (need Bash/`fetch_usage_oauth.py`, disabled in trials), the cloud ping routine's management (needs RemoteTrigger), and the vault heartbeat format. B2 intentionally unused.

## Dataset construction

- Source: `skills/claude-maxer/SKILL.md` (sha256 recorded in `suite.json` as `skill_sha256_at_creation`), plus CLAUDE.md notes on this skill.
- Author: generated by Claude with the `skill-bench` skill, then label-audited by an independent subagent that saw only the SKILL.md and the prompts, not the author's labels.
- Label agreement: **31/31 (100%)** on trigger cases; none dropped. Mildly ambiguous per the auditor: t-005 ("cut off"), t-011 (digests, obsidian-local pull), t-101 (vault-tasks overlap), t-104 (API "rate limits"). t-010 may legitimately fire skill-bench as well.
- Rubric changes from the audit: b-001 `h2` pinned to "hour 2 of the window"; b-002 `active` accepts "loop is disabled / todo-triage has no input"; b-003 `vaulttask` accepts "commits" instead of "pushes"; b-004 reference accepts env-overridable defaults; b-007 `noassert` now fails a flat claim of *either* state (SKILL.md says enabled, CLAUDE.md says disabled 2026-08-12); b-008 `env` accepts hedging about the gate and daily cap.
- The auditor also found an inconsistency in SKILL.md: "Loop stop conditions" still says "either window >= 95%", which is left over from the flat gate the ramp replaced. That's a skill defect, not a suite defect, so it was left for skillopt.
- Splits: `dev` (for iterating on the skill, e.g. by skillopt), `test` (held out; only for scoring). Stratified by label and category.

## Known limitations

- The judge is a Claude model grading Claude output.
- Cases run in the real repo, so results depend on the installed skill set and global CLAUDE.md at run time.
