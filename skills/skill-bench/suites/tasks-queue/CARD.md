# Benchmark card: `tasks-queue`

## What is measured

- **Trigger**: does the model call `Skill(tasks-queue)` when it should (recall), and stay quiet when it shouldn't (precision / false-positive rate)?
- **Behavior**: once the skill is used, does the agent do what the skill's contract says **against a real task list**? Behavior cases are *world cases*: each runs in a sandbox holding its own `Tasks.md`, with `tasks_queue.py` pointed at it through the `TASKS_QUEUE_FILE` test seam. They are graded on decisions (what it says is next), tool calls (did it go through `tasks_queue.py`), and the file's end state (what got checked off). The judge only covers what code can't see.

Profile (see the vault note `0_dev/0_AI/1_SKILLS/benchmarking.md`): input = prompt + world · output = decision + actions · grader = check + state, with a judge for the rest.

## Capability spec (derived from SKILL.md at creation)

Trigger claims
- **T1**: fires when the user asks about their tasks / task list / Tasks.md (including in Chinese).
- **T2**: fires on "what's next to do" / "any undone tasks" / what should Claude pick up from the user's list.
- **T3**: fires on spare-capacity requests: "use up my limit", "leverage the limitation", spare quota → what can Claude work on.
- **T4**: fires when `tasks-queue` is named.

Non-trigger claims
- **N1**: claude-maxer's own territory (pausing/scheduling maxer, 5h window questions that ask for no work) belongs to claude-maxer.
- **N2**: "task" in another sense (celery/gradle tasks, task managers, code questions) is not the queue.
- **N3**: requests owned by neighbouring skills (learning-instruct, context-summarize, skill-bench, paper-fetch).
- **N4**: off-topic requests.

Behavior claims
- **B1**: asked what to work on, it reads the queue through `tasks_queue.py` (`pick`/`next`/`list`) and offers the first undone Tasks.md item before anything else.
- **B2**: with no undone vault items, it says so and follows the queue's next tier (the daily news batch) rather than inventing tasks.
- **B3**: an indented line under a list item is a continuation of that item, not a separate task.
- **B4**: checking off goes through `tasks_queue.py mark` and changes exactly that item to `- [x] <text>`, leaving the others alone. This holds for plain `- ` items too (the note predates checkboxes).
- **B5**: never tracks tasks anywhere but Tasks.md (no TODO.md or other list).

Not covered: the optimize tier (needs git repos under the apps root and a PR flow), `--small`/`--skip` (claude-maxer's interface, not a user-facing one), and `news-ran` bookkeeping.

## Dataset construction

- Source: `skills/tasks-queue/SKILL.md` and `tasks_queue.py` (sha256 of SKILL.md recorded in `suite.json` as `skill_sha256_at_creation`). The worlds copy the real vault note's format: headings per project, `- [x]`/`- [ ]` items, and one wrapped continuation line.
- Author: generated by Claude with the `skill-bench` skill, then label-audited by an independent subagent that saw only the SKILL.md and the prompts, not the author's labels.
- Label agreement: **24/26 (92%)** on trigger cases. The auditor marked two as ambiguous, both because of description overlaps: `tq-t03` ("what's next to do?", which memory-orchestrate also claims as "what's next?") and `tq-t06` ("5h window" is claude-maxer's cue). Both were rewritten, not dropped. Behavior audit: `tq-b05/noinvent` was reworded so a legitimate optimize-tier suggestion can't fail it, and `tq-b06`'s reference no longer assumes writes are impossible. The other behavior flags assumed ungated mark claims and real news state; the state checks and the world's env redirection already cover those.
- Overlaps the audit surfaced (description-level, not fixed here): tasks-queue's "mentions tasks" is overbroad, since read literally it fires on celery tasks. "use up my limit" and spare quota co-fire with claude-maxer.
- Splits: `dev` (for iterating on the skill, e.g. by skillopt), `test` (held out; only for scoring). Stratified by label and category.
- Smoke runs on dev (2026-09-28) fixed three harness issues before freezing: skill scripts not reachable in the world, unscoped `Read` letting a trial read the real vault, and harmless `echo` wrappers being denied. They also fixed one ambiguous rubric item ("completed items listed as done" was graded as "listed as pending").

## Worlds

| world | state | decision it tests |
|---|---|---|
| `two-open` | 2 undone items (the first has a wrapped continuation line), 4 done | next = the upload task; count = 2; mark one |

## Known limitations

- The judge is a Claude model grading Claude output.
- World trials run under an allowlist (`suite.json` → `sandbox`). A legitimate call the allowlist misses shows up as a "sandbox denials" warning in the report. Read that before blaming the skill.
- Trigger cases run in the real repo, so results depend on the installed skill set and global CLAUDE.md at run time.
- `tq-b04` exercises a known script bug found while building the suite: `mark` on a plain `- item` writes `- [x] - item`. It is expected to fail until `mark_done` is fixed.
